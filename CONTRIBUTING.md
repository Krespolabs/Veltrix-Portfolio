# Contributing

Thank you for helping improve the Veltrix portfolio.

## Before contributing
- Read `AGENTS.md`, `README.md`, and relevant documentation under `docs/`.
- Check open issues to avoid duplicate work.
- For substantial changes, open an issue or discuss the proposed approach first.

## Workflow
1. Create a focused branch from the default branch.
2. Make a small, clearly scoped change.
3. Update relevant documentation and project status.
4. Run applicable checks and record the results.
5. Open a pull request using the provided template.

## Standards
- Use clear names and straightforward implementations.
- Keep accessibility, mobile responsiveness, performance, and security in scope.
- Do not add dependencies without a clear reason.
- Do not commit secrets, private data, generated build output, or unrelated files.
- Do not make unsupported claims about products, users, results, or deployment status.

## Pull requests
A pull request should explain the problem, solution, affected areas, verification performed, and any risks or follow-up work. Include screenshots for meaningful UI changes.
